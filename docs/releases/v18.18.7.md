# v18.18.7

omc now matches [oh-my-pi](https://github.com/can1357/oh-my-pi) v18.18.7. Upstream had 877 commits since v18.17.0. About 330 of them don't apply to omc (changelog edits, upstream's own CI, the Rust shell, collab and spotlight), and the rest were ported to C. I checked the result against the real `omp` 18.18.7 running next to omc on the same mock model: the first request each one sends, the TUI, RPC and ACP.

This is also the first release with prebuilt binaries, so you no longer need a compiler to try it.

### Install

```sh
curl -fsSL https://raw.githubusercontent.com/buzzer-re/Oh-My-C/main/install.sh | sh
```

The installer picks the binary for your system, checks it against `SHA256SUMS` and puts `omc` in `~/.local/bin`. If you'd rather build it on your own machine, pass `--build`:

```sh
curl -fsSL https://raw.githubusercontent.com/buzzer-re/Oh-My-C/main/install.sh | sh -s -- --build
# or, from a clone: ./install.sh --build
```

| Archive | Runs on |
|---|---|
| `omc-18.18.7-linux-x86_64.tar.gz` | Linux x86_64 with glibc 2.35+ and OpenSSL 3 (Ubuntu 22.04+, Debian 12+, Fedora 36+) |
| `omc-18.18.7-linux-arm64.tar.gz` | Linux arm64, same requirements |
| `omc-18.18.7-macos-arm64.tar.gz` | macOS on Apple silicon |
| `omc-18.18.7.tar.gz` | the source, for anything else |

The macOS binary has OpenSSL built in, so you don't need Homebrew to run it. It isn't notarized, though: if you download it with a browser, run `xattr -d com.apple.quarantine omc` once.

Building from source needs a C11 compiler, make, and the OpenSSL 3 and zlib headers. On Debian/Ubuntu that's `build-essential libssl-dev zlib1g-dev`, on Fedora `gcc make openssl-devel zlib-devel`, and on macOS the Xcode command line tools plus `brew install openssl@3`.

### The ask tool takes an HTML form

Upstream replaced the `questions[]` list in `ask` with a single HTML `<form>`. omc has its own parser for it, written from scratch in C. The TUI draws the form as a paged dialog with dropdowns, text fields, "Other" answers, validation and `<img>` pictures, and `ask.timeout` submits whatever was filled in so far. RPC clients walk the form one field at a time, and ACP clients get it as a form elicitation.

Inline `<svg>` pictures aren't drawn yet. They show the same row omp shows when a picture fails to render.

### Providers

- Google Antigravity is back behind an at-your-own-risk warning: a new login asks you to type `yes`, and model lists mark it "(at your own risk)"
- Morph sends the prompt-cache key as `x-session-id`, on both Chat Completions and Responses
- Gemini's `MALFORMED_RESPONSE` is retried as a transient error on every transport
- A 429 or 402 whose message reads like a context overflow is now treated as a rate limit
- Auth rules can pause a provider with `disabled "<reason>"`
- OpenAI image edits send several input images as `image[]`
- Cursor edits show as one card with their diff, and tool batches keep their order around native edits
- The Claude Code fingerprint is updated to 2.1.321

### Tools

- bash: `cd somewhere; cmd` runs the command in that directory, using omp's exact rules for the leading `cd`. Deny rules win over prompt rules across a whole command line, and your own rules win over a project's. Commands run with a `C.UTF-8` locale.
- bash: a call that arrives while the session shell is busy runs in a copy of it, with the same variables, functions, options and working directory (traps aren't copied)
- grep highlights the pattern in its header, and zero matches is one line saying `0 matches`
- LSP: source actions, push and pull diagnostics merged, `.erb` files, and `lsp.enabled` also turns off diagnostics after write/edit
- URL reads refuse bot-challenge pages, and xAI web search stops after 2 turns
- Image generation lists why each provider failed, and truncated JPEGs are rejected
- Zig syntax highlighting

### TUI and sessions

- Whatever you type while omc is starting up is kept, and the Enter you press submits it
- A skill written during a session reaches the model right away
- `/restart` relaunches with the session restored
- Title generation counts toward `--max-cost`
- Retries after `--model pi/<role>` walk that role's fallback chain
- Plan mode only treats an approved plan as the reference, and `/plan` pause closes an open review
- `/export` takes an absolute path

### Fixed while comparing against omp

These were already wrong before this update. The side-by-side runs against omp caught most of them; the first two came from a real session.

- A message queued while the model was still generating a tool call (yours, or a subagent's) made omc skip that call, so a long `write` was thrown away and the model had to write it again. Tool calls the model already generated now always run, as they do in omp.
- Resizing the terminal left the scrollback wrapped at the old width, with copies stacked on top of each other and rows of tool cards missing. Once a resize settles, omc now redraws the transcript at the new width (`tui.resizeScrollback`, default `rebuild`).
- Pressing Esc while the model was still streaming a tool call kept the half-finished call, so the next request carried it and the screen showed an `F5 to retry` row that omp doesn't. Only calls that finished streaming are kept now.
- `<think>` and `<thinking>` blocks from local and third-party models showed up as plain text. They become thinking blocks while they stream, for every provider that isn't an official endpoint.
- HTML in messages (`<p>`, `<br>`, lists, `<code>`, entities) printed as raw tags
- F5 and `/retry` didn't follow omp's rules for what to retry, including replaying a tool batch that failed completely and saying "Nothing to retry"
- A tool call that reused an earlier turn's call id removed that turn's card from the screen
- Calling a tool that doesn't exist gave a generic error instead of `Tool <name> not found. Did you mean <tool>?`
- Pointing a built-in local provider at a dead endpoint with an environment variable failed without the header warning omp shows
- Over RPC, `abort` answered before the run had actually stopped
- Surrogate entities such as `&#xD800;` drew differently from omp

### Not in omc

Some of upstream's work isn't ported, either because it builds on parts of omp that omc doesn't have, or because it's a lot of C for what it gives: credential pools and Codex plan routing, cloud model discovery, Hindsight memory, JS eval with `agent()` and `workpool()`, the browser tool, collab, spotlight and OTEL. omc also keeps running your system's bash instead of omp's Rust shell, on purpose. The full list is in [docs/status.md](https://github.com/buzzer-re/Oh-My-C/blob/main/docs/status.md).

### Known differences

- Tool calls in one batch run one after the other; omp starts them together
- bash doesn't stream progress over RPC the way omp's does
- The `read` and `ask` tool descriptions mention SQLite queries, RAR/7z archives, jq filters and inline SVG, which omc doesn't do yet
- MCP `!command` header and env values are sent as written instead of being run
