# v19.1.0

omc now matches [oh-my-pi](https://github.com/can1357/oh-my-pi) v19.1.0. Upstream had 1,159 commits since v18.22.0 (1,456 with merges). About 750 of them don't apply to omc (changelog edits, upstream's CI and tests, the Rust shell, the browser and its Chrome extension, the `computer` tool, the omp daemon, Tern's native views), and the rest were ported to C. As before, I checked the result against the real `omp` 19.1.0 running next to omc on the same mock model.

### Install

```sh
curl -fsSL https://raw.githubusercontent.com/buzzer-re/Oh-My-C/main/install.sh | sh
```

On Windows 10/11, in PowerShell:

```powershell
irm https://raw.githubusercontent.com/buzzer-re/Oh-My-C/main/install.ps1 | iex
```

Already on 18.22.0? Just run `omc update`.

To build it on your own machine instead:

```sh
curl -fsSL https://raw.githubusercontent.com/buzzer-re/Oh-My-C/main/install.sh | sh -s -- --build
# or, from a clone: ./install.sh --build
```

| `omc-19.1.0-linux-arm64.tar.gz` | Linux arm64, same requirements |
| `omc-19.1.0-macos-arm64.tar.gz` | macOS on Apple silicon |
| `omc-19.1.0-windows-x86_64.zip` | Windows 10 (1809+) and 11 on x64: `omc.exe`, plus `libomc.dll` under `lib\` |

The macOS binary isn't notarized: if you download it with a browser, run `xattr -d com.apple.quarantine omc` once. The Windows one isn't code-signed either, so SmartScreen may ask before it runs a copy downloaded with a browser.

### omc runs on Windows

This one is new: omc now builds and runs natively on Windows, with no WSL, no Cygwin and nothing extra to install. `omc.exe` imports only Windows' own DLLs. TLS goes through Schannel and the crypto through CNG, and omc has its own deflate, so there's no OpenSSL or zlib to ship. It's the same omc: same TUI, tools, prompts, sessions and config, in `%USERPROFILE%\.omc`.

The bash tool runs real bash, from Git for Windows, and finds it the way omp does. Next to it, the model gets a `powershell` tool for the things that only make sense on Windows: the registry, services, WMI, ACLs. Without Git Bash, the bash tool runs PowerShell and says so. The TUI handles Windows Terminal and the classic console, including Shift+Enter, AltGr and dead keys through win32-input-mode, like omp does on ConPTY.

`omc update` works there too, and so does `libomc.dll` if you want to embed omc in your own program (it ships in the zip, with its import library and a `.def` for MSVC). Every release is now built and tested on a Windows runner like the other platforms. More in [docs/windows.md](https://github.com/buzzer-re/Oh-My-C/blob/main/docs/windows.md).

### Tools are commands now

This is the big one. The rarely used tools (`lsp`, `debug`, `github` and friends, plus your MCP tools) don't sit in the tool list anymore. While `bash` is on, the model runs them as commands inside a bash call: `lsp --help`, `lsp references src/main.c`, `github pr view 12 | head`. Their docs live at `help://<tool>`. Staged edits, plan submission and issue reports went the same way, through `resolve`, `reject`, `propose` and `report_issue`.

omp does this inside its own shell. omc keeps your system's bash, so each command is a small shell function that calls back into the running omc over a private socket. From the model's side it's the same thing.

### Ask questions without losing the composer

The ask form is now one stacked panel above the composer instead of taking its place. Answered questions fold down to what you picked. If you'd rather just say something, type it: sending a message skips the questions, and the model gets whatever you'd already answered.

### Composer predictions

After each turn, omc asks the model what you'll probably say next and shows it faint in the empty composer. Tab or → takes it. It costs one small request per turn; turn it off in `/settings` under Interaction if you don't want it.

### Edit by describing the change

The new `magic` edit mode (`edit.mode: magic`) lets the model describe changes in plain Markdown under `# path` headings, and a fast model of your choice turns that into the actual edits.

### Kiro

Kiro is a built-in provider now: `/login kiro` with IAM Identity Center, Builder ID, Google, GitHub or a Kiro API key, and `/usage` shows your credits.

### Other things worth knowing

- Switching models keeps your thinking level, and only lowers it when the new model can't do it
- `/handoff` runs in the background, so the current answer keeps streaming
- `?` at the start of a message asks it as a `/btw` side question
- Full command output goes to `local://N.log` files you can read and list, instead of `artifact://` links
- bash takes a `notify` option that wakes the session when a background command prints something you're waiting for
- Failed retries stay out of the transcript, and the retry row tells you why it's retrying
- Prompt-cache warming has strategies (`auto`, `keepalive`, `compact`) and can compact a prompt before its cache expires
- MCP speaks the 2026-07-28 protocol, with longer deadlines for tools that report progress
- `google-gemini-cli` is gone, as it is upstream

### Not in omc

The omp daemon (shared MCP servers across sessions), the Chrome extension and browser relay, Binary Ninja and the other disassemblers, JS eval and selective commits, Tern's native views and on-device speech are still not ported, and omc still runs your system's bash instead of omp's Rust shell, on purpose. The full list is in [docs/status.md](https://github.com/buzzer-re/Oh-My-C/blob/main/docs/status.md).
