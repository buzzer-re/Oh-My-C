# v19.1.1

omc now matches [oh-my-pi](https://github.com/can1357/oh-my-pi) v19.1.1. Upstream had 410 commits since v19.1.0. About 280 of them don't apply to omc (changelog edits, upstream's CI and tests, the Rust natives and shell, the browser, the `computer` tool, JS eval, `/tan` and `/omfg`), and the rest were ported to C. As before, I checked the result against the real `omp` 19.1.1 running next to omc on the same mock model.

### Install

```sh
curl -fsSL https://raw.githubusercontent.com/buzzer-re/Oh-My-C/main/install.sh | sh
```

On Windows (PowerShell):

```powershell
irm https://raw.githubusercontent.com/buzzer-re/Oh-My-C/main/install.ps1 | iex
```

Already on 19.1.0? Just run `omc update`.

To build it on your own machine instead:

```sh
curl -fsSL https://raw.githubusercontent.com/buzzer-re/Oh-My-C/main/install.sh | sh -s -- --build
# or, from a clone: ./install.sh --build
```

| Archive | Runs on |
|---|---|
| `omc-19.1.1-linux-x86_64.tar.gz` | Linux x86_64 with glibc 2.35+ and OpenSSL 3 (Ubuntu 22.04+, Debian 12+, Fedora 36+) |
| `omc-19.1.1-linux-arm64.tar.gz` | Linux arm64, same requirements |
| `omc-19.1.1-macos-arm64.tar.gz` | macOS on Apple silicon |
| `omc-19.1.1-windows-x86_64.zip` | Windows 10 (1809+) and 11 on x64: `omc.exe`, plus `libomc.dll` under `lib\` |
| `omc-19.1.1.tar.gz` | the source, for anything else |

The macOS binary isn't notarized: if you download it with a browser, run `xattr -d com.apple.quarantine omc` once. The Windows one isn't code-signed either, so SmartScreen may ask before it runs a copy downloaded with a browser.

### Magic edit works on a draft

In the `magic` edit mode, the fast model that turns your model's change description into edits now works on an in-memory draft: it can read and search the file, and each replace is checked as it goes. When a replace doesn't fit, it gets a hint and tries again, without losing the ones that already worked. The finished draft is written in one go, and a JSON file is syntax-checked before anything touches the disk.

### Tool schemas as omp sends them

On OpenAI, Codex and Azure, tool schemas now go through omp's cleanup and its strict-mode conversion, so what the model receives is the same as with omp. MCP tools whose schemas OpenAI used to refuse (lookaround patterns, `oneOf`, bare objects) now just work, and MCP tools are sent the way omp sends them.

### Other things worth knowing

- A `tree` status line segment (opt-in) shows where you are in the session tree after a rewind or on a branch
- `/wt` runs the new worktree's `post-checkout` hook, with a spinner, and picks up the skills and commands it creates
- Alt+P refreshes the model list in the background once it's two hours old
- A billing error from a provider moves on to your fallback models
- `eval` tells the model about its default 30-second deadline

### For programs embedding omc

`omc_set_result_filter` lets a program that embeds libomc rewrite every tool result before the model sees it: built-in tools, MCP tools and its own. The API version is now 2.

### Not in omc

Per-model `@upstream` pins, online model lists for Copilot, Z.AI and Codex, the omp daemon, the Chrome extension and browser relay, the `computer` tool, Binary Ninja and the other disassemblers, JS eval and selective commits, Tern's native views and on-device speech are still not ported, and omc still runs your system's bash instead of omp's Rust shell, on purpose. The full list is in [docs/status.md](https://github.com/buzzer-re/Oh-My-C/blob/main/docs/status.md).
