# Testing

`make test` builds and runs every unit test, builds `examples/embed`, then runs the e2e suite. It
needs a C compiler and `python3` (for the mock servers). It needs **no network access, no real
credentials and no omp install**. The parity harnesses that compare against a live `omp` are
separate developer tools (below).

Rule of thumb: prefer the mock servers. Real-model checks cost the user's tokens and are only for
behavior a mock cannot reproduce.

## Unit tests (`tests/test_*.c`)

Each test is a standalone C program whose `main` returns non-zero on failure. The Makefile links
each one against only the objects it exercises (`T_test_<name>` lists), so several tests stub
catalog or auth symbols and run without the rest of the program.

| Test | Covers |
|---|---|
| `test_text` | regex (Rust syntax, linear engine and backtracking fallback), glob/gitignore, walker, search, YAML, fuzzy |
| `test_tui` | ANSI width/slicing, components, editor, keys, fuzzy, markdown, renderer; golden markdown/thinking/user-bubble captures from omp (`tests/tui/golden`) |
| `test_chrome` | welcome banner and status band against omp captures (`tests/fixtures/chrome`) |
| `test_toolcards` | tool card renderers against omp captures (`tests/fixtures/toolcards`) |
| `test_planreview` | plan review overlay against an omp capture (`tests/fixtures/planreview`), section delete/undo feedback, annotations, option commit |
| `test_outsink` | OutputSink/output-meta port against strings captured from omp 18.14.2 |
| `test_providers_ag` | Anthropic and Google request shaping, recorded SSE streams |
| `test_providers_oai` | Chat Completions, Responses (Azure, Codex), Ollama |
| `test_providers_google` | Vertex ADC (RS256 JWT, token exchange, caching, impersonation), Cloud Code Assist envelopes, healing, schema normalizer, onboarding, against an in-process loopback server |
| `test_providers_bedrock` | SigV4 (AWS test suite), event-stream framing, request mapping, stream state machine |
| `test_cursor` | protobuf codec, Cursor schema, Connect framing |
| `test_ws` | WebSocket keys, framing, loopback session (fragmentation, ping, close, oversize/masked-frame rejection) |
| `test_auth` | every login engine and custom hook against `tests/e2e/mock_auth.py` |
| `test_editmodes` | replace / patch / apply_patch / sloppy against omp's pi-edit fixtures (`tests/fixtures/pi-edit`, copied verbatim) and the Codex apply_patch scenarios |
| `test_readfmt` | archives, SQLite, PDF, notebooks against fixtures generated by `tests/readfmt_fixtures.py`, plus a deterministic mutation fuzzer (skips without python3) |
| `test_judgment` | judge question validation, keyword prompts, reply parsing |
| `test_memory` | memory job store semantics, redaction, lessons, consolidation, managed skills |

`test_http` (manual network smoke test) and `tests/tui_demo.c` (interactive TUI playground) are
not part of `make test`.

Run one test with `make build/tests/test_text && ./build/tests/test_text`.

## End-to-end suite (`tests/e2e/run.sh`)

The suite drives the real `build/omc` binary against local mocks. It creates a throwaway agent dir
(`OMC_CODING_AGENT_DIR`) whose `models.yml` defines a `mock` provider on a random port, sets
`OMC_NO_TITLE=1`, and runs `check <name> <expected substring> <command...>` assertions covering
tools, sessions, edit modes, xd:// devices, MCP, eval, DAP, RPC (including host tools), ACP, the
library example, providers and logins.

`tests/e2e/mock_openai.py` is a scripted Chat Completions server. The **last user message decides
the reply**, so a test is just a prompt:

| Prompt | Mock behavior |
|---|---|
| `bash:<cmd>`, `write:<path>:<text>`, `read:<path>`, `glob:<pat>`, `grep:<pat>`, `edit:<input>`, `todo:<a,b>` | stream that tool call, then echo the tool result as text (`Tool said: …`) |
| `call:<tool>:<json args>` | stream an arbitrary tool call |
| `calls:[[tool, args], …]`, `seq:[[tool, args], …]` | issue the scripted tool calls one per request (multi-step flows such as read → edit, grep → edit) |
| `say:<text>` | stream text word by word |
| `md:<fixture>`, `think:<thinking>\|<text>`, `slow:<s>:<text>` | display scenarios used by the TUI harness |
| `fail:<status>:<msg>`, `streamfail:<text>` | HTTP and in-stream errors |
| anything else | `plain answer` |

It also answers eval `completion()`/`judge()` side requests and the memory pipeline stages, and
logs every request body to `$MOCK_LOG` for assertions (`reqlog.py`).

Other mocks reach real provider code paths through `OMC_PROVIDER_URL_REWRITE` /
`OMC_AUTH_URL_REWRITE` (origin → mock path prefix), always with fake credentials:

| Mock | Exercises |
|---|---|
| `mock_bedrock.py` | Bedrock ConverseStream, SigV4 and bearer auth |
| `mock_google.py` | Google OAuth token endpoint, Vertex and Cloud Code Assist |
| `mock_cursor.py` | Cursor RunSSE/BidiAppend, exec frames |
| `mock_devin.py` | Devin Cascade Connect stream (`providers_devin.sh`) |
| `mock_gitlab.py` | GitLab Duo and Duo Workflow WebSocket (`providers_gitlab.sh`) |
| `mock_providers.py` | credential transports: URL, bearer and headers built from stored logins (`providers_transport.sh`) |
| `mock_auth.py` | device-code, oauth-code, api-key validation, custom hooks (`omc login` over stdin) |
| `mock_mcp.py`, `mock_mcp_oauth.py` | stdio MCP tool; OAuth-protected streamable-HTTP MCP |
| `mock_dap.py` | scripted debug adapter |
| `rpc_client.py`, `acp_client.py`, `eval_client.py` | protocol drivers for RPC, ACP and multi-cell eval sessions |
| `acp_session.py` | `omc acp` as an editor drives it: session lifecycle (load replay, resume, fork, close), configOptions, steering, refusal, usage, and a fake client advertising fs / terminal / form elicitation for the bridges, plus client `mcpServers` |
| `editor_io.py` + `fake_editor.sh` | the interactive composer under a pty: Ctrl+G through a scripted `$EDITOR`, Ctrl+R, paste chips and the large-paste menu, raw paste through a fake `xclip`, `#` actions / `#N` refs, `@` mentions (checked in the mock's request log) |

All Python is run with `python3 -I`.

## Request parity (`tests/parity/request_diff.sh`)

```sh
tests/parity/request_diff.sh [prompt] [cwd]     # needs `omp` installed (OMP_BIN overrides)
```

This runs omp and omc in print mode on the same prompt and cwd, against the same mock, with
throwaway agent dirs. It then compares the **first model request**: the tool list and order, each
tool's description and parameters, request parameters, the system prompt (diffed into
`$RD_DIR/sys.diff`) and the messages. The only normalization is the product name (`omp's` →
`omc's`, `omp://` → `omc://`). `RD_SETUP=<script>` seeds both agent dirs (skills, rules,
settings, edit modes); `RD_WORKSETUP=<script>` runs `<script> <cwd>` before each app's run, so
files a tool modifies are reseeded for the second app. The tool messages of each app's last request
are written to `$RD_DIR/tools.{omp,omc}` and diffed (`tool messages: identical`), which is how tool
result text is checked byte for byte against omp. Use it after any change to prompts, tools, schemas,
tool output or discovery.

## ACP parity (`tests/parity/acp_diff.py`)

```sh
tests/parity/acp_diff.py [scenario ...] [--only omp|omc] [--keep] [--full-commands]
```

This drives `omp acp` and `omc acp` with the same scripted JSON-RPC client against the same mock (throwaway
agent dirs and HOME) and diffs every frame each agent sends, in arrival order. A fake client answers
permission requests and, when a scenario advertises them, `fs/*`, `terminal/*` and `elicitation/create`.
Ids, timestamps, the work and agent dirs, versions, durations and the product name are normalized; the
slash-command registry is compared by name. Scenarios: `basic` (initialize, auth, config options, modes,
list, steering, ext methods, close, error codes), `tools`, `errors` (stop reasons), `load` (replay, resume,
fork), `bridge`, `elicit`, `steer` (steering into a running turn, cancel), `mcp` (client mcpServers), `edit`
(diff content), `plan`, `planform` (plan approval with and without form elicitation). Run it after any change
to `src/modes/acp.c` or to what tools report.

## TUI parity (`tests/tui/`)

| Tool | Purpose |
|---|---|
| `compare.sh start [cols rows]` / `keys` / `shot` / `diff` / `restart` / `replay <spec>` / `stop` | run omp and omc side by side in tmux against the mock with throwaway agent dirs and HOME (the user's `~/.omp` is never touched); send identical keys; capture plain and ANSI panes |
| `celldiff.py a.ansi b.ansi [anchor]` | cell-level diff (glyph, fg, bg, attributes) of two captures |
| `mksession.py spec.json cwd out.jsonl` | write an omp v3 session from a compact spec (`tests/tui/specs/*.json`), so `replay` renders identical transcripts and tool cards in both apps without running tools |
| `mkgolden.py` | cut a region of an omp capture into a golden file |
| `mock_mcp.py` | MCP server for MCP card checks |

Environment knobs: `CMP_DIR`, `OMP_BIN`, `CMP_SETUP=1` (keep omp's wizard), `CMP_NOMODEL=1`,
`CMP_CONFIG` (extra config.yml lines), `CMP_SPLIT=1` (separate work dirs), `CMP_SEED`, `CMP_NAME`,
`CMP_WAIT`, `CMP_ENV` (extra environment for both apps, e.g. `EDITOR=tests/e2e/fake_editor.sh` for Ctrl+G). Use the omp version that `omp --version` reports, and re-check captures when it changes.

## Golden captures

Goldens are `tmux capture-pane -e` output from omp (theme titanium, truecolor, unicode glyphs, mock
model, 120 columns unless noted):

- `tests/tui/golden/*.ansi`: markdown fixtures (`tests/tui/fixtures/*.md`), thinking, user bubble
  (`test_tui`)
- `tests/fixtures/chrome/*.ansi`: welcome and status band (`test_chrome`)
- `tests/fixtures/toolcards/*`: tool cards (`test_toolcards`)
- `tests/fixtures/planreview/`: plan review overlay and its plan (`test_planreview`)

To refresh one: reproduce the screen with `compare.sh`, capture omp with `shot`, cut it with
`mkgolden.py`, and confirm that omc's rendering matches before committing.

## Adding tests

- **New module:** add `tests/test_<area>.c`, give it a `T_test_<area>` object list in the Makefile,
  and append it to `UNIT_TESTS`.
- **New provider:** offline request/stream tests in `test_providers_*.c` from recorded streams. If
  login or URL shaping matters, add a mock under `tests/e2e/` and route to it with the URL rewrite
  variables.
- **New tool or behavior:** add an e2e `check` driven by a mock prompt (extend `mock_openai.py` if
  the script language lacks it). For wire changes, run `request_diff.sh`.
- **New UI:** compare against omp with `compare.sh`, then freeze the result as a golden fixture so
  `make test` guards it without omp.
- Never use real credentials or the user's agent dir. Always use a temp `OMC_CODING_AGENT_DIR` /
  `PI_CODING_AGENT_DIR`.
- Never let a test reach a real endpoint. Route every provider, search and usage URL to a mock
  (`OMC_PROVIDER_URL_REWRITE` or the per-provider base URLs).
- In e2e shell scripts, give every mock its own PID/port variable names. `run.sh` sources its sub-scripts
  into one shell, so a reused name (`CPID`) leaks a mock past the `EXIT` trap. The traps also kill
  `$(jobs -p)` as a backstop.

## Running several builds or agents on one machine

The dev VM has 7.7 GB RAM, a 4 GB swap file that a reboot drops (`sudo swapon /swap`), and a RAM-backed `/tmp`.
Parallel suites and omp comparisons have OOM-killed it, so when more than one build or agent runs at once:
- Put temp files on disk: `export TMPDIR=/home/neo.guest/omc-scratch/tmp/<name>`.
- Build with `make -B -j3`. `-B` is needed because the shared filesystem has clock skew.
- Run the full suite one at a time: `flock -o /home/neo.guest/omc-scratch/test.lock make test`. The `-o`
  matters: without it the mocks the suite spawns inherit the lock fd, and an orphaned mock holds the
  lock forever.
- Keep at most one tmux omc/omp comparison alive, and kill it right after the capture. Never
  `pkill` by pattern; another run's mocks may match.
- `sed -i` here resets file modes to 0600, so restore them from git afterwards (`run.sh` and the e2e
  scripts must stay executable).
- `#ifdef __APPLE__` code never compiles on Linux, so run `build-tools/check_apple.sh` after touching it.

## Sanitizer runs (ASan + UBSan)

glibc lets some heap overflows and use-after-frees run without crashing, so they can pass every test on Linux and still crash on macOS. That happened on 2026-11-02 with `/settings` (options overflow), the Agent Hub (use after `hub_close`) and an RPC turn-end rewind (freed event message). Before a release or after memory-heavy changes, build a sanitized copy in a separate worktree (it uses ~2.6 GB) and run both suites:
```sh
git worktree add --detach ../omc-asan main && cd ../omc-asan
LDFLAGS="-fsanitize=address,undefined" make -B -j3 OPT="-O1 -fsanitize=address,undefined -fno-omit-frame-pointer"
export ASAN_OPTIONS=detect_leaks=0:halt_on_error=0:log_path=$PWD/san/asan UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=0:log_path=$PWD/san/ubsan
mkdir -p san && ./tests/e2e/run.sh            # unit tests: build build/obj/<plat>/tests/test_* the same way and run each
ls san/                                       # must be empty
```
Keep `halt_on_error=0` and the `log_path` settings. Otherwise the first finding aborts each run and is printed into the test output, failing hundreds of checks and hiding later findings. At `-O1`, GCC also prints a few known false-positive warnings (a NULL format string in `xvasprintf`/`sb_vappendf`, and `memmem` in `highlight.c`).

## Image pipeline

- `tests/test_img.c`, `test_img_jpeg.c`, `test_img_webp.c`: codecs against Pillow-decoded references generated
  at test time by `tests/img_fixtures.py` (PNG exact, GIF / lossless WebP exact, JPEG / lossy WebP within a
  tolerance), malformed-input fuzzing, encoder round trips (own decoder + Pillow), and the `resizeImage` /
  `loadImageInput` ports.
- `tests/e2e/images.sh` (sourced by `run.sh`): read-tool notes and the wire image (1568x882, <= 500 KiB),
  undecodable and magic-byte detection, text-only metadata, the Anthropic per-image clamp against
  `mock_providers.py`, session blob persistence and resume.
- TUI: `CMP_IMAGES=1 tests/tui/compare.sh start` + `compare.sh paste <path>` reproduces a pasted / dropped image
  path in both apps (chips, band, transcript, request).
